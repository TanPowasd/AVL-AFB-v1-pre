# 缓存攻防（Cache Duel）· 公开赛制

本文件仅包含公开赛制与运行边界，不包含任何其他选手的提交、成绩或日志。

- **游戏**：双角色在线缓存攻防博弈。单局由一名攻击方（attacker）与一名防守方（defender）在参数 `(C, K, N)` 上交互 `N` 步。
- **交付**：单个 UTF-8 Python 3.10+ 文件，最终统一提交至 `../submissions/cache_duel.py`（题内开发可选放 `agents/submissions/my_agent.py`）。同一文件按开局 `role` 字段同时支持攻防两角色。
- **通信与依赖**：独立子进程 `stdin / stdout` 逐行 UTF-8 JSON；仅允许 Python 标准库，禁止联网与读写外部文件，`PYTHONHASHSEED=0`，`stderr` 丢弃。
- **计时规则**：单步基础时限 `1.0` 秒；每局共享时间池 `5.0` 秒（不回补，余额见 `time_pool`）；每局总思考时间硬上限 `20.0` 秒。超时、崩溃、提前 EOF 或非法 JSON 将导致进程终止，剩余步全按犯规处理。
- **犯规替代与技术判负**：
  - 攻击方输出非法 key（非整数、`bool` 或越出 `0 <= k < K`）→ 裁判替换为常量 `0`。
  - 防守方需驱逐时输出非法 `evict`（非整数、`bool` 或不在当前缓存内）→ 裁判强制驱逐最新放入缓存的 key。
  - **正式评分零容忍**：本方在某局出现任意一次犯规、超时或进程死亡（`faults > 0` 或 `dead == true`），该局直接判技术负得 `0` 分。
- **单局计分**：记离线最优 Belady/MIN 在实际请求序列上的缺失数为 `OPT`，防守实际缺失数为 `M_def`：
  - `def_score = OPT / M_def`（`M_def == 0` 时为 `1.0`）
  - `att_score = 1 - def_score`
- **正式百分制评分（scoring_v2）**：固定对阵 7 个参考对手，覆盖 3 组标准配置 `(8, 64, 3000)`、`(32, 256, 5000)`、`(64, 4096, 5000)`，每次评测由操作系统安全随机源独立抽取 `64` 个不重复种子并互换攻守（共 `2688` 局）。总分 = `0.5 * 防守均分(0~100) + 0.5 * 攻击均分(0~100)`，对手、配置、种子等权。
- **本地自测与隔离**：只允许对阵公开基线（`fifo` / `lru` / `marking` / `rand`）或自身镜像；结果、回放与日志必须保存在当前工作区 `results/`、`replays/`、`logs/` 内。禁止读取外部目录、互测其他选手提交、修改工作区标记或使用 `--unrestricted` / `--serve`。

权威裁判源码以 `engine/engine.py` 为准，详细协议与数值见 `handbook/player-guide.md` 与 `handbook/game-facts.md`。
