## 来源与代码边界

用户授权阅读指定参考目录。`references/d15/manifest.json` 记录原始 d15 压缩包 SHA256、静态解码文件 SHA256 和字节数。原参考保持独立保存。

本候选并非全部从零编写，也不是全套 d15 的直接包装。复用了 d15 的以下可读模块并修改：

| 本目录模块 | 原模块 | 用途 |
|---|---|---|
| rules.py | gpt6_rules.py | 官方规则提取快照、动作及价格 |
| daily.py | gpt6_policy.py | 每天按观测建立任务链 |
| routes.py | gpt6_math_routes.py | 带物料和时限的路线插入搜索 |
| projects.py | project_model.py | 作物/动物有限时域 DP |
| forecast.py | market_model.py | 商店与公开产能情景 |
| market_model.py | exact_market_model.py | 逐单位价格和日流量估值 |
| portfolio.py | portfolio.py | 整体产能组合增量交换 |
| prior_bank.py / belief.py | inventory_bank.py / inventory_belief.py | 可选历史先验和公开库存区间 |

`economics.py` / `certified.py` 保留阅读实验使用的改写参考类，不是默认入口。
`agent.py` / `strategy.py` / `market.py` / `budget.py` / `evaluate.py` / `panel.py` 为此任务编写的集成、采购、限时和评测逻辑。

在线入口不读取其它项目目录，不执行参考中的整季动作表。日内队列由当前观测生成。历史库用于未来供需分布，不是当前对手未来行动；库含 1200 条日记录，训练来源由其 team/episode 字段标识。不能把含未知重叠的种子宣称为完全独立的最终测试。

## 尚未解决的近似

- 经济模型按天处理交付时机，日内真实到款和共同仓容更复杂。
- 物料的跨日持有与未来投入存在市场往返近似。
- 当前初始投资仍有阶段参数；不是全季完全最优。
- 对手作物物料消耗的物理预测仍需与增产假设联动。
- 复用 DP 的部分通用配置仍按标准 10×10、30 天比赛编写。
- 外部对手的运行时间单列；原生研究评测采用更宽的外层 watchdog，再独立核算我方官方时间预算，不能冒称真实天梯已通过。

## r4 / r5 记录

r4 的 12 个种子、两个版本和双座次共 48 局全部完成且有效：较早组合规划平均输 60,248.96，较晚组合规划平均输 42,141.08；双方均 0 胜 24 负。

r5 已集中增加以下研究开关后统一运行测试：

- `terminal_cash`：最后一天只比较有最终到款路径的工作，允许按收益选更多雇工，预留回仓及部分卸货修复时间。
- `route_feedback`：通过最忙几天的实际路线覆盖修正未来劳动力价格；中断的价格更新事务回滚。
- `net_crop_inputs`：物理场景中的对手增产必须同时扣肥料输入；历史库沿用其原始残差定义，不再重复扣。
- `paid_costs`：未来成本抵扣组合确实使用的已购种子/动物，避免已支出款项再次影响选择。
- `hold_inputs`：给小麦和肥料保留有限自用库存，净市场成交守恒；边际估值穿过保留库存策略重新计算。

r5 的 32 项单元/回归测试全部通过。官方 `kaggle-environments` 单局（对 0909、seed3、seat0）完整有效，平均输 22,921，累计超时 0.939 秒。此处仍是一局开发验证，不是稳定胜率证据。

r5 完整对抗报告为 `experiments/integrated_twelve_r5/report.json`。运行时冻结快照独立，不受后续代码修改影响。
